# Discovery deadlines and useful history (2026-10-21)

This change addresses a reported whole-disk scan that showed an expected Lark IPC socket and a generic npm timeout under the same incomplete label. The previous discovery runner shared ten seconds across unrelated tools, with two seconds per query. A later npm installation could be refused even while every preceding query was completing normally. Partial sessions also skipped historical publication; oversized root projections discarded every row for that root.

## Shipped behavior

Each non-npm tool query and the npm inventory have independent discovery runners. Equivalent fixed tool commands are deduplicated within one invocation. Queries retain a ten-second execution deadline, 64 KiB stdout and 64 launch attempts per family. Completed launched attempts renew the thirty-second admission inactivity window. Native observations and installation enumeration retain operation/data/count limits and cancellation; synchronous kernel calls cannot be forcibly interrupted. Layout discovery renews its five-second window at valid checkpoints. File traversal has no ninety-second or other absolute elapsed-time cutoff.

The ordinary `ProbeRunner::new` contract retains its absolute batch deadline for Git, activity and caller-authorized tool operations. This is not a global relaxation of execution containment. A timed-out required cache query records `probe_timeout`, including command and limit, and later installations can still be inspected. Launch-count exhaustion and admission deadline remain `probe_budget` with distinct details. Missing optional tools are normal absence; present tools returning failures or unusable paths are discovery gaps. JSON adds `toolQueryFailures` without renaming existing fields.

The TUI distinguishes file-read omissions, application/tool location gaps, and normal exclusions/optional notifications. Skipping an IPC socket does not appear as an unchecked file location. Machine coverage/status and execution guards remain conservative. Fresh partial subtree sizes remain visible as lower bounds; historical sizes have an explicit Previous/上次 prefix and cannot contribute to current selection totals.

Regular TUI history is available before fresh tool discovery. Records bind request family, loaded rule bytes, native root identity and a common publication generation. Only the latest matching generation supplies first paint; fresh discovery replaces the working roots. Partial scans may retain positive historical rows and preserve unobserved siblings. Sparse projections prioritize outer candidates and larger known/lower-bound sizes under the existing per-root owned-data estimate. Individually oversized rows, unknown prior storage and cancellation preserve old records. Encoded-file, disk, root, input and retained-data limits still apply; a failed merge write leaves the prior file in place.

History does not prove current coverage, activity, classification or cleanup permission. Default junk traversal still uses `reuse=None`, current native bulk length observations and fresh directory enumeration. Neither empty FSEvents HistoryDone nor a fixed flush/wait proves a recursive tree unchanged; existing APFS probes also do not justify that inference. Whole-subtree skipping remains unimplemented. See [scanner/cache contracts](scanner-and-cache.md) and [the native change-evidence probe](macos-change-evidence-2026-10-07.json).

## Validation on macOS

Host: macOS 26.5.2 (25F84), arm64, Rust 1.98.0 pinned by the repository. Runtime checks use the optimized local build. No OS cache purge was performed; measurements below are single acceptance observations, not comparative speed benchmarks or percentile estimates. No user cleanup was confirmed.

- Controlled slow discovery: six isolated nvm-style npm launchers sleep 2.1 seconds for each required cache query; pip independently sleeps three seconds. Discovery took 20.102 seconds including installed Homebrew npm, returned all six fixture caches, `npmDiscovery.complete=true`, no tool-query failures and exit 0. This exceeds the old ten-second batch deadline while preserving positive results.
- Controlled partial history: a fixture Homebrew cache contains an IPC socket. Cold and warm scans finish with exclusions. The warm first historical frame arrived in 0.099 seconds, before the three-second current pip query completed. Enter navigation worked during discovery; reasons, Space feedback, navigation and q worked after completion.
- Between those runs, the fixture payload changed from 8,192 to 16,384 bytes. An independent ordinary walk observed 16,384 bytes in Homebrew; the final grouped current lower bound was 16,403 bytes including the 19-byte pip fixture. Historical data did not become execution authority.
- Real regular cleanup: live inspection during traversal, category/owner navigation, file details, reasons and selection feedback were exercised. Go was independently rechecked, selected, previewed and cancelled. The remaining discovery failures identified the OSDK npm shim and `pnpm store path` exiting with status 1. Independent direct read-only queries confirmed both OSDK shims had no selected version; these were configuration failures, not timeouts. The Lark socket was shown in the exclusions section. This is regular-mode acceptance, not proof of whole-disk completeness or iTerm2 renderer acceptance.

The first real pass exposed two whole-root historical projection omissions. The bounded sparse fallback removed both warnings on the final acceptance pass. It retained 782 presentation-only rows in 79 root records (6,897,065 encoded bytes), while the current result contained 1,087 candidates. These counts describe that changing host, not a guaranteed workload. Reopening the same state showed a historical frame after 0.190 seconds; immediately exiting preserved all 79 cache payload hashes. The 55.259-second final real acceptance includes navigation and review; it is not a measured traversal duration or a speedup comparison. Its release binary SHA-256 was `0e7494fcc6d8408ac72ff31fb372f1355d2f18cd32b349be7db1a0f5ce89078c`; a subsequent bounded diagnostic-string allocation change was covered by the final installation tests and lint/build pass.

## Verification results

- `cargo fmt --all --check` and `git diff --check`: passed.
- `cargo clippy --workspace --all-targets --all-features -- -D warnings`: passed on the pinned macOS host toolchain.
- Workspace cross-target Clippy for `x86_64-unknown-linux-gnu` and `x86_64-pc-windows-gnu`, all targets/features with warnings denied: passed. Zig’s cache had to be redirected to a writable temporary directory after the initial Linux C build was denied access to the default cache. No production cfg was widened.
- Native `cargo test --workspace --all-features -- --test-threads=1`: passed before the final sparse-preview/partial-size refinements. Passing results for unchanged crates were reused. The final affected runs were Core 432 unit tests plus five integration tests (three existing opt-in benchmarks ignored), CLI 77 unit tests and 89 integration tests (four existing native pnpm-cleanup tests ignored), and TUI 140 tests. The final diagnostic allocation adjustment was followed by all 19 installation tests. No executed test failed in these final runs.
- Initial sandboxed FSEvents tests failed because streams could not start. They were kept and passed under normal native permissions. A first history-generation test caught mixed old scopes; the fixed regression now requires only the latest prior generation before discovery.
- The existing ignored matrix consists of five opt-in native benchmarks and four native pnpm-cleanup acceptance tests. Those nine tests were not executed by the workspace command; no ignored test is described as passed.
- VitePress client/server build and page rendering: passed through the installed Homebrew Node executable. The ambient npm OSDK shim could not run the package script because no npm version was selected; no user tool configuration was changed.
- Release build: passed; the existing `~/.local/bin/sweepx` link points to the rebuilt repository binary.
 Existing ignored benchmarks and explicit native pnpm-cleanup acceptance tests are not counted as executed. Linux/Windows cross-target lint checks compilation of platform branches; their runtime behavior was not verified on those systems.
